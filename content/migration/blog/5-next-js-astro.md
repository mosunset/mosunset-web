このサイトは「たのしく、つくる。」をテーマに、作ったものや集めているものを置いている場所です。

前回の「大改修5回目」では、Next.js と迷った末に **Astro + Keystatic** を選んだ理由を書きました。あれから 1 年。結局、また作り直しました。大改修 6 回目です。

今回選んだのは **TanStack Start** と **Cloudflare**（Workers・D1・R2）です。この記事は、何を変えて、何を変えなかったのかの記録です。

## 変えなかったこと：「人生のインベントリ」という考え方

前回いちばん大事にしていたのは、このサイトを「ブログ」ではなく「人生のインベントリ（持ち物の目録）」として作る、という考え方でした。

- **本**：著者、出版社、ISBN、読書状況
- **楽器**：種類、メーカー、モデル
- **資格**：実施団体、分類、取得日
- **おもちゃ**：フィギュア、ぬいぐるみ、ストラップなど（今回から追加）

それぞれ持っている項目が違うものを、型で守りながら管理したい。この考え方は今回もそのままです。

変わったのは置き場所です。前回は Astro のコンテンツコレクション（`config.ts` の Zod スキーマ）でしたが、今回は `src/lib/collections.ts` に「種類ごとの項目の定義」を 1 か所だけ書いています。その定義から、次の 3 つを作っています。

- 管理画面の入力欄
- サーバーでの入力チェック
- 公開ページの表示

項目を 1 つ足したいときは、定義を 1 行足すだけで済みます。

## 変えたこと：Git の中のファイルから、データベースへ

前回の構成では、記事もコレクションも Git のリポジトリの中の Markdown ファイルでした。Keystatic の画面から書けるとはいえ、中身はファイルです。書いたものを公開するには、コミットしてビルドし直す必要がありました。

今回は、データを **Cloudflare D1**（SQLite のデータベース）に、画像を **Cloudflare R2** に置くようにしました。サーバーは **Cloudflare Workers** で動いています。

- 管理画面で保存すると、ビルドしなくてもすぐにサイトに出る
- 画像がリポジトリに溜まっていかない
- 本の ISBN を入れると、書名・著者・表紙を自動で埋められる

D1 は [Drizzle ORM](https://orm.drizzle.team/) で扱っていて、テーブルの定義も TypeScript で書いています。型で守るという点は、前回から変わっていません。

## 入稿の体験：管理画面を自分で作った

前回の「最強のスキーマ、最弱の入稿体験」の問題は、Keystatic が解決してくれました。今回は、その管理画面を自分で作っています。

- **エディター**：[Tiptap](https://tiptap.dev/) を使い、`/` で見出しや画像を入れられるようにした
- **画像**：ブラウザの中で縮小して WebP にしてからアップロードする
- **書きかけの保護**：保存前の内容をブラウザに残しておき、タブを閉じても戻せる
- **並べ替え**：コレクションの並び順をドラッグで変えられる
- **プレビュー**：公開ページと同じ見た目で確かめられる

ログインには [Clerk](https://clerk.com/) を使い、決まったアカウントだけが管理画面に入れるようにしています。

## なぜ TanStack Start なのか

前回は「Next.js の誘惑を振り切って Astro」でした。今回 Next.js ではなく TanStack Start を選んだのは、次のような理由です。

- **ルーティングが型で守られる**：リンク先や URL のパラメーターを間違えると、書いている時点でエラーになる
- **サーバーの処理を関数として呼べる**：`createServerFn` で書いた処理を、画面からそのまま型付きで呼べる
- **Cloudflare で素直に動く**：Vite の上で動くので、Cloudflare の Vite プラグインと組み合わせやすい

静的なサイトが得意な Astro から、データベースとログインのあるアプリ寄りの構成に変わりました。それに合ったフレームワークを選んだ、というのがいちばん近いと思います。

## 遊び：プレイグラウンドもそのまま

「ガチガチの基盤があるからこそ、安心して遊べる」という考え方も変わっていません。

前回の Astro のサイトにあったプレイグラウンドは、React で作り直してすべて移しました。

- [文字数カウント](/playground/character-count)
- [ハッシュ生成](/playground/hash-generator)
- [ブラウザで物体認識](/playground/webyolo)（TensorFlow.js）
- [Kuromoji 形態素解析](/playground/kuromoji)
- [3D ブロック](/playground/3dblock)（three.js）

どれもブラウザの中だけで動き、入力した内容をサーバーに送らないようにしています。一覧は[プレイグラウンド](/playground)にあります。

## 見えないところ

作り直したついでに、見えないところも整えました。

- **検索・AI 向け**：ページごとの構造化データ（JSON-LD）、RSS、AI 向けにサイトの中身をまとめた `llms.txt`
- **セキュリティ**：セキュリティ関連の HTTP ヘッダー、脆弱性の連絡先を書いた `security.txt`
- **お問い合わせ**：[Cloudflare Turnstile](https://www.cloudflare.com/products/turnstile/) でいたずらを防ぎ、届いたらメールで知らせる

## おわりに

大改修 6 回目を経たこのサイトは、「あらゆるものを構造化して管理したい」という考え方はそのままに、置き場所を Git からデータベースへ、入稿を自作の管理画面へと移しました。

7 回目があるかどうかはわかりません。ただ、今回はデータがファイルから切り離されたので、次に作り直すことになっても、中身はそのまま持っていけるはずです。

この地盤の上で、これからも「たのしく、つくる。」を続けていきます。
