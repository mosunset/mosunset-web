ちょうど 1 年前、「大改修5回目」という記事を書きました。Next.js の誘惑を振り切って Astro を選んだ、という話です。締めくくりには、こう書いています。

> 僕の「インベントリ思想」をAstroほどエレガントに解決してくれるフレームワークは、今のところ他にありません。

……はい。作り直しました。大改修 6 回目です。

今回選んだのは **TanStack Start** と **Cloudflare**（Workers・D1・R2）。Astro が悪かったわけではありません。このサイトでやりたいことのほうが、少しずつ変わっていきました。

## 「書いたらすぐ出てほしい」

前の構成では、記事も本の一覧も楽器の一覧も、すべてリポジトリの中の Markdown ファイルでした。Keystatic のおかげで画面から書けてはいたものの、中身はあくまでファイルです。本を 1 冊足すだけでも、コミットして、ビルドして、デプロイして、ようやくサイトに出ます。

最初はそれで満足していました。でも、本を買うたびに、資格を取るたびにこれをやっていると、だんだん面倒になってきます。写真も 1 枚足すたびにリポジトリが重くなっていきました。

「管理画面で保存したら、その場でサイトに出てほしい」

それだけのことを叶えたくて、データの置き場所をファイルからデータベースに移すことにしました。

## Cloudflare にまとめた

置き場所は Cloudflare にまとめました。

データは **D1**（SQLite）、写真は **R2**、サイトそのものは **Workers** で動いています。D1 は [Drizzle ORM](https://orm.drizzle.team/) で扱っていて、テーブルの定義も TypeScript で書けます。前回いちばん大事にしていた「型で守る」は、ここでもちゃんと続いています。

## フレームワークは TanStack Start に

データベースがあって、ログインがあって、管理画面がある。こうなると、静的なサイトが得意な Astro よりも、アプリ寄りのフレームワークのほうが素直に書けます。

前回の流れからすると、今度こそ Next.js……となりそうなところですが、選んだのは TanStack Start でした。決め手は 3 つです。

1. **ルーティングに型が付く。** リンク先のパスや URL のパラメーターを間違えると、書いている時点でエディターが教えてくれる
2. **サーバーの処理を関数として呼べる。** `createServerFn` で書いた処理を、画面からそのまま型付きで呼べる
3. **Cloudflare の上で素直に動く。** Vite の上で動くので、Cloudflare の Vite プラグインと組み合わせやすい

特に 1 つめは、一度慣れると戻れません。URL を変えると、その URL を使っている場所がすべてエラーになります。そのおかげで、安心して大きく直せます。

## 管理画面は自分で作った

Keystatic を手放したので、管理画面は自分で作ることになりました。せっかくなので、自分が使いやすいように欲張っています。

エディターには [Tiptap](https://tiptap.dev/) を使い、`/` を打つと見出しや画像を入れられるようにしました。写真はアップロードする前にブラウザの中で縮小して、WebP にします。書きかけの内容はブラウザに残しておくので、うっかりタブを閉じても消えません。

中でも気に入っているのが本の登録です。ISBN を入れるだけで、書名・著者・表紙が自動で埋まります。前の構成では、ここを全部手で打っていました。あの頃の自分に見せてあげたいです。

ログインには [Clerk](https://clerk.com/) を使い、自分のアカウントしか管理画面に入れないようにしています。

## 変えなかったこと

ここまで変えたことばかり書いてきましたが、根っこの考え方は前回と同じです。

このサイトは、ブログというより「人生のインベントリ（持ち物の目録）」です。本・楽器・資格・おもちゃ。それぞれ記録したい項目が違うものを、型で守りながら管理したい。

前回は、それを Astro のコンテンツコレクションで実現していました。今回は `src/lib/collections.ts` という 1 つのファイルに、種類ごとの項目をまとめて書いています。管理画面の入力欄も、サーバーでの入力チェックも、公開ページの表示も、すべてこの定義から作ります。項目を 1 つ増やしたいときは、ここに 1 行足すだけです。

ちなみに、今回から **おもちゃ** のコレクションも増えました。フィギュアやぬいぐるみ、ストラップなどを少しずつ載せていく予定です。

## プレイグラウンドも引っ越した

もう 1 つ変わらないのが、「ガチガチの基盤があるからこそ、安心して遊べる」という考え方です。

前のサイトにあった[プレイグラウンド](/playground)は、React で作り直して全部持ってきました。[文字数カウント](/playground/character-count)のような実用寄りのものから、[ブラウザで物体認識](/playground/webyolo)や [3D ブロック](/playground/3dblock)のような遊び寄りのものまであります。どれもブラウザの中だけで動くので、入力した内容がサーバーに送られることはありません。

引っ越しの途中で、[Kuromoji 形態素解析](/playground/kuromoji)が「辞書を読み込んでいます」のまま止まる、という不具合にも出会いました。サーバーが圧縮して送った辞書をブラウザが先に展開し、それを kuromoji がもう一度展開しようとして失敗していたのが原因です。こういう地味なハマりどころも、作り直しの醍醐味だと思うことにしています。

## 見えないところも少しだけ

作り直したついでに、見えないところも整えました。

検索エンジンや AI に内容を読み取ってもらいやすいように、ページごとに構造化データを出し、RSS と `llms.txt` も置いています。セキュリティ関係の HTTP ヘッダーを付け、脆弱性を見つけた人のための連絡先として `security.txt` も用意しました。

どれも見た目は何も変わりませんが、ちゃんとしたサイトに一歩近づいた気がしています。

## おわりに

1 年前の自分は、あの構成を「現時点での最適解」と書いていました。今の自分も、たぶん同じことを書きます。そしてきっと、また作り直します。

ただ、今回はひとつだけ前と違うことがあります。データがファイルから切り離されて、データベースに入りました。次にフレームワークを変えることになっても、中身はそのまま持っていけるはずです。

大改修 7 回目があるかどうかはわかりません。それまでは、この地盤の上で「たのしく、つくる。」を続けていきます。
